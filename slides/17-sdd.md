# Erst die Anforderung klären.
Dann die Änderung umsetzen.

Specification-Driven Development (SDD) am Beispiel der Demo:

## Karten

### Specify

Leere Titel ablehnen; gültige Titel weiter akzeptieren.

### Plan

Validierung und Testfälle vorab abstimmen.

### Tasks

Betroffene Methode und Tests eingrenzen.

### Implement

Ändern, lokal testen und den Diff erklären.

## Kernaussage

Eine klare Spezifikation erleichtert den Review. SDD ist eine Option, kein Teamstandard.

## Sprechernotizen

SDD ist Teil unserer Workshop-Inhalte und bleibt laut Kickoff-Stand eine Option, kein beschlossener Standard. Die Spezifikation macht erwartetes Verhalten sichtbar. Sie garantiert weder korrekten Code noch sichere Aktionen. Wir lassen den Demo-Agenten zuerst einen Plan liefern, bevor wir die kleine Änderung bestätigen.
